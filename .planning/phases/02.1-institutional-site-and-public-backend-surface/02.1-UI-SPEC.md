# Phase 02.1 UI-SPEC: Institutional Site

## Intent

Present a credible, calm and premium public face for a historical strategy MMO.
The site should explain the fantasy and the gameplay loop quickly, then make
support and legal information easy to find. It must feel related to the mobile
shell without pretending to be the game itself.

## Visual contract

- Use semantic theme names from `packages/tooling/design-tokens/index.ts`:
  `bg.base`, `bg.sunken`, `surface.raised`, `border.subtle`, `text.primary`,
  `text.secondary`, `accent.bronze`, `accent.gold`, `accent.steel`, `danger` and
  `success`.
- Use only the existing spacing scale `xs` through `3xl`, radius scale `sm`
  through `full`, typography roles `display`, `title`, `heading`, `body`,
  `label` and `caption`, and motion roles `instant` through `deliberate`.
- Desktop layout is responsive from narrow mobile widths to wide screens. Content
  uses a single readable measure; decorative art never carries required meaning.
- Primary call-to-action uses `accent.bronze`; informational links use
  `accent.steel`; `accent.gold` is reserved for emphasis. Text contrast must meet
  the existing token-level WCAG AA contract.

## Page composition

- Shared header: product mark, links to Game, Support and Legal, locale selector,
  and one primary “Play on mobile” action that does not imply web gameplay.
- Home: one clear value proposition, three gameplay pillars, a short server-
  authoritative trust statement, mobile-store placeholder link treatment, and a
  footer with legal/support links.
- Game/features: explain city, world, alliance and warfare in four sections with
  headings and concise copy.
- Support: accessible form with field-level errors, success/failure status and a
  visible alternate contact path when delivery is unavailable.
- Privacy and terms: long-form readable content with table of contents only when
  it improves navigation; no marketing elements interrupt the legal text.

## Interaction and accessibility

- All links and controls are keyboard reachable in document order, have visible
  focus, and use text labels or accessible names.
- Use semantic `header`, `nav`, `main`, `section`, `aside` and `footer` landmarks.
- Respect `prefers-reduced-motion` by collapsing non-essential transitions to the
  `instant` token.
- Locale selection is a normal link or GET form; it never mutates server state.
- Error, success and unavailable-mail states are announced with an appropriate
  live region and are preserved after validation failure.

## Content rules

- Product name comes from `config('game.name')`.
- Public copy is translated in pt-BR, en and es; no user-facing string is embedded
  only in a controller or Blade component.
- Do not promise a launch date, store availability or online feature that is not
  backed by the current roadmap.
