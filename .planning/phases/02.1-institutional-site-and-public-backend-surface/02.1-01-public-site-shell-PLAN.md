# Plan 02.1-01: Laravel public site shell and localized page routes

## Goal

Replace the stock Laravel root page with a public, server-rendered institutional
surface that is isolated from game state and supports the three project locales.

## Requirements

- REQ-16

## Tasks

<task>
<read_first>
- apps/api/routes/web.php
- apps/api/resources/views/welcome.blade.php
- apps/api/config/game.php
- .planning/phases/02.1-institutional-site-and-public-backend-surface/02.1-CONTEXT.md
</read_first>
<action>
Create `Game\Platform\Interface\Http\InstitutionalSiteController` (or the
existing project-approved public interface location) with read-only actions for
`home`, `features`, `support`, `privacy` and `terms`. Register named GET routes
`site.home`, `site.features`, `site.support`, `site.privacy` and `site.terms` in
`apps/api/routes/web.php`. Add locale middleware/request handling that accepts only
`pt-BR`, `en` and `es`, defaults to `pt-BR`, and never writes a session or game
state. Render every page through `layouts/institutional.blade.php`; use
`config('game.name')` for all product-name output and remove the stock welcome view
from the root route.
</action>
<acceptance_criteria>
- `php artisan route:list` contains the five named `site.*` GET routes.
- `apps/api/routes/web.php` contains no `welcome` view return for `/`.
- The controller or view source contains `config('game.name')` and no literal product name.
- `./vendor/bin/pest --filter PublicRoutesTest` exits 0 and asserts status 200 for all five routes in each supported locale.
</acceptance_criteria>
</task>
